# SDED 2.0 publication status

Prepared September 8, 2026. Status: **publication candidate; not deposited or published on Zenodo**.

The intended destination is a new version in the existing SDED Zenodo series, concept DOI [10.5281/zenodo.17418488](https://doi.org/10.5281/zenodo.17418488). The verified prior version is v1.1, [10.5281/zenodo.17418489](https://doi.org/10.5281/zenodo.17418489). The repository's v1.2 development files do not establish a v1.2 Zenodo release.

The public record API responded, but Zenodo's login and upload pages returned HTTP 504. Repeated attempts to retrieve the deposited PDFs timed out. Authenticated ownership, existing drafts, and the new-version action could not be inspected. No new DOI has been reserved and no upload or publication action has been represented as successful.

## Prepared package

- `paper/SDED-2.0.md`: complete manuscript, including abstract, domain audits, research agenda, and all eighteen requested deliverables.
- `output/pdf/SDED-2.0.pdf`: typeset reading edition.
- `data/examples.json`: structured audit records derived from the manuscript, with proposal status.
- `data/chord-quality-matrix.json`: explicit chord-quality coordinates and conventional symbols.
- `research/HISTORY.md`: recovered chronology and source limitations.
- `CONTRIBUTING.md`: participation and review rules, with optional TM styling.
- `.zenodo.json`: proposed descriptive metadata; it does not create a deposit.
- `output/SDED-2.0-source.zip`: source and data package, excluding private recovery files.
- `output/SHA256SUMS.txt`: checksums for the PDF and source archive.

## Publication continuation

When access works, inspect the authenticated account and the existing series before creating a new version. Retrieve and compare the original deposited PDFs, then update the visible historical limitation if resolved. Use the existing series' new-version action and inspect any existing draft first to avoid duplicates. Upload the verified package, check title, creator, version, license, and prior-version relationship, and verify the public DOI and downloadable files after publication. Do not reuse the v1.1 DOI as the identity of the 2.0 manuscript.

The proposed descriptors are clearly labeled as proposals, not independently validated replacements. Publication is dissemination of the framework and research agenda, not a claim of completed empirical validation.
